# Capture slots: how the site shows what HorneroOS looks like

Every product image on the site is a real host capture with provenance.
There are no renders, mock-ups, concept images or captures of the previous
(pre-Signal) appearance. The site shows a curated selection, not the whole
archive: pending (deferred) and archived captures never render publicly —
there are no placeholder plates. `docs/IMAGE_CURATION.md` records every
keep, archive, defer and cancellation decision.

## The slot is the contract

`src/data/capture-slots.json` is the single source of truth. Each slot
(`CAP-<AREA>-<NN>`, for example `CAP-HERO-01`) declares:

- what must be on screen (`title`, `description`, `alt`, in Spanish and
  English), its capture `session` and `priority` (P0 launch-critical, P1
  important, P2 complementary);
- the exact geometry: `aspect`, `width`, `height`, whether a `scale2x`
  master is wanted, and the `format` (PNG master for screenshots, WebM+MP4
  plus a poster for clips, AVIF/JPG for photographs);
- the staging: `theme`, `mode`, `layout`, `wallpaper`, the `setup` steps to
  reach that state on the capture machine, and the `privacy` rules;
- inventory metadata: `pages` records where a slot was originally intended;
  it no longer drives rendering (see the editorial layer below).
- its `status`: `pending` (deferred, `file: null`), `captured` (with
  `file`, `sha256`, `capturedAt`, and optional `source`, `pins` and
  `credit`), or `archived` (asset and record kept, rendering stopped).
  Its `curation` decision (`FEATURE`, `SUPPORT`, `DOCS`, `ARCHIVE`,
  `DEFER`) and an optional `docsOnly` flag complete the record.

`src/data/captures.ts` types and re-exports the data. Do not hand-edit
`docs/CAPTURE-SHOT-LIST.md`: it is generated from the data file by
`node scripts/gen-shot-list.mjs`, and `npm run check:captures` fails when it
is stale. The shot list groups the slots into capture sessions with the
global environment, privacy and export rules.

## The editorial layer

`src/data/editorial.json` decides what renders publicly: per route, ordered
sections (`hero`, `pair`, `compare`, `selector`, `support`, `clip`,
`strip`) with ordered slot ids, a human caption in Spanish and English, an
optional CSS `crop` (framing of the original asset — never a new file) and
`render: manual` (the page component places it in its own layout) or
`render: gallery` (`CaptureGallery` renders it). The showroom is the same
file's curated groups. Captions state what the image demonstrates;
provenance is stated once per page, not per figure. Only `captured`,
non-`docsOnly` slots may be placed — the checker enforces it.

## Rendering

One component renders every slot everywhere: `CaptureFigure`
(`src/components/CaptureFigure.astro`). It renders the real file (or, for
clips, the looping video with its poster) and throws at build time for a
pending, archived or docs-only slot. `CaptureLabel` states honestly what
the image is: a real Hornero Signal capture or clip, or a real photograph.
`LookCompare` wipes between the two editorial compare slots.

Social cards (`public/og/`, generated by `scripts/build-og.mjs`) never embed
a desktop screenshot; they pair the brand with site data (the showroom card
counts captured slots by priority, from the data file).

Rendered documentation (from HorneroOS/docs, pinned) may still reference the
removed `/images/apps/...` captures. `src/lib/remark-docs-links.mjs`
replaces those images with a pending-capture note naming their slot
(`CAP-TERM-06`, `CAP-TERM-01`) instead of a broken link (legacy behaviour).
The supported docs-image mechanism is the stable public URL: docs pages
embed `https://horneroos.com/captures/cap-<id>.png`, served from
`public/captures/` copies that the checker requires to be byte-identical to
the `src/assets/captures/` originals. File names there are a stable API:
never rename them. `CAP-TERM-06` and `CAP-TERM-01` already resolve this
way; docs-only slots (`docsOnly`) exist only for this mechanism.

## Taking and delivering a capture

1. Read the slot's brief in `docs/CAPTURE-SHOT-LIST.md` (global rules
   included): demo user, fixed 1920×1080 scale-1 output, shipped wallpapers
   only, released composition, no personal data anywhere in frame.
2. Shoot it on the capture machine with `scripts/capture-helper.sh`
   (`shot`, `window`, `region`, `clip`, then `verify CAP-ID file`).
3. Fill the slot: `node scripts/capture-ingest.mjs CAP-ID file` validates
   the size and aspect ratio, copies the file to `src/assets/captures/`
   (clips: `public/captures/` plus a poster in `src/assets/captures/`),
   records its checksum and flips `status` to `captured`. Use `--pins`,
   `--source` and `--credit` for provenance. `--archive` keeps the asset
   and record but stops rendering (remove its editorial placements too);
   `--reset` deletes the file and returns the slot to pending — never use
   it to archive.
4. Add the placement to `src/data/editorial.json`, run `npm run build` and
   look at the page.

Adjust the slot's `alt` text to what the final frame really shows before
ingesting.

## What may stay: kept images

Not every image in the repository is a product capture. Brand marks,
favicons, social cards, third-party application logos shown nominatively,
licensed wallpapers are listed, with a
category and a reason, in `src/data/kept-images.json`. Anything else image-
or video-like in `public/`, `src/assets/` or `assets/` fails the build.

`npm run check:captures` (run by `npm run build`, which also runs it with
`--dist` over the built pages) enforces all of the above: well-formed
slots, ES/EN copy, captured and archived files present with matching
checksums (clips included), editorial placements captured-only with every
captured slot placed or docs-flagged, byte-identical `public/captures`
copies, duplicate-content slots fully archived, every slot id mentioned in
source declared, editorial placements rendering in both locales with no
archived/pending leakage and no placeholder text, the shot list up to
date, and no unaccounted showcase image anywhere. The old showroom collection
(`src/content/showroom/`), `public/images/`, `assets/screenshots/` and
`src/assets/concepts/` must not come back.
