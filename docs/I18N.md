# Internationalization

All site copy lives in **typed message catalogs** under
`src/i18n/messages/` — one file per page/component, plus `ui.ts` for
shared chrome (navigation, footer). There are no `isEs ? '…' : '…'`
boolean ternaries anywhere under `src/`; `scripts/check-i18n.mjs`
fails the build if the `isEs` identifier reappears.

## How a catalog looks

```ts
import type { Locale } from '../ui';

const es = {
  title: 'Página no encontrada',
  // Interpolation is a function; both locales share the signature.
  showing: (count: number): string => `Mostrando ${count} resultados.`,
  // Structured copy (arrays/objects) is fine too.
  steps: [{ title: 'Descargá', text: '…' }],
};

export type Messages = typeof es;

const en: Messages = {
  title: 'Page not found',
  showing: (count: number): string => `Showing ${count} results.`,
  steps: [{ title: 'Download', text: '…' }],
};

export const messages: Record<Locale, Messages> = { es, en };
```

Components take the current locale and read their catalog:

```astro
---
import { messages } from '../../i18n/messages/not-found';
const m = messages[locale];
---

<h1>{m.title}</h1>
```

Spanish is the **source shape**: write `es` first, then satisfy it in
every other locale. `en: Messages` makes a missing or mistyped key a
compile error in `astro check`, and `Record<Locale, Messages>` makes a
missing locale object one too.

## Adding a locale (e.g. `pt`)

1. Add `'pt'` to `locales` in `src/i18n/ui.ts` and to the `i18n` block
   (plus sitemap locales) in `astro.config.mjs`.
2. `astro check` now fails in every catalog that lacks `pt` — work
   through them: add `const pt: Messages = { … }` and include it in the
   exported record. The compiler is the checklist.
3. Extend `localizePath`/`localeFromPath` in `src/i18n/ui.ts` for the
   new URL prefix, and add the `src/pages/pt/` route tree
   (thin wrappers passing `locale="pt"`, like `src/pages/en/`).
4. `node scripts/check-i18n.mjs` verifies catalog parity, the `isEs`
   ban, and the story/capture-slot bilingual fields.

## Client-side strings

Browser scripts cannot call catalog functions. Pages that need
client-side copy define plain template entries with `{placeholder}`
slots (see the `client*` keys in `messages/wallpapers.ts`), serialize
the needed subset as a JSON island
(`<script type="application/json" …>`), and fill placeholders in the
client script.

## Data with `es`/`en` fields

Structured data files (for example `src/data/story.ts` and
`src/data/capture-slots.json`) keep `{ es, en }` field pairs and are
indexed directly: `entry.title[locale]`. The parity gate checks those
stay complete.
